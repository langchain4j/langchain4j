# Decision v2 implementation plan

## Goal

Deliver two alternative PRs, core and community, implementing the approved
[design](../specs/2026-09-25-decision-system-one-design.md). Keep the
existing PRs open; draft explanatory comments for approval before posting.

## Core (this repository)

1. Open types: change `Question.java` to a plain interface. Replace the
   monolithic `DecisionAnswer.java` class with an interface and add
   `NoulAnswer`, `ChoiceAnswer`, `ScoreAnswer`, and `ConfidenceProvenance` in
   `experimental/langchain4j-experimental-decision/src/main/java/dev/langchain4j/model/decision/`.
   Update `DecisionResponse` to map answer interfaces. First add
   tests for a custom question and answer and typed standard answers; run the
   focused Maven test to observe RED, then implement and observe GREEN.
2. Add immutable per-answer metadata and confidence provenance. Test missing
   provenance, out-of-range confidence, defensive copies, and heterogeneous
   answer maps before implementation. Migrate existing answer tests to the
   new typed API and rerun the module tests.
3. Add `DecisionReceipt` and its test in the same source/test
   package. Cover ordered questions/options, schema version, returned values,
   confidence provenance, unknown answer names, and omitted answers. Observe
   RED before implementation and GREEN afterward.
4. Run `mvn -pl experimental/langchain4j-experimental-decision -am
   test -DskipITs`, format/check as the module requires, then install the
   snapshot locally with `mvn -pl
   experimental/langchain4j-experimental-decision -am install
   -DskipTests -DskipITs`. Commit the verified core change and open its new PR.

## Community (separate repository and worktree)

5. Branch from the existing community PR without changing it. Add a dedicated
   `models/langchain4j-community-system-one` module and register it in the
   parent POM. Move shared request encoding, response decoding, and HTTP
   handling behind public `SystemOneDecisionModel`. Test generic
   JSON System One, KEV extra fields, Laya no-auth/no-model, unknown answers,
   and unsupported features before implementation (RED/GREEN).
6. Update `models/langchain4j-community-typesafe` to depend on the new module,
   preserving `TypeSafeDecisionModel`'s builder/default behavior
   through delegation. Test the public TypeSafe path and compatibility of its
   request/response mapping before implementation (RED/GREEN).
7. Add `ClmDecisionModel`, `ClmRequestParameters`, and ranking
   request/result types in the System One module. Test per-call temperature,
   latency header, ranking wire shape, and invalid inputs (RED/GREEN).
8. Add provider-specific openjev and djev models in the System One module.
   Test data-URL images, openjev image count, djev multipart parts, and djev
   mixed standard/span requests with typed span answers (RED/GREEN).
9. Run Maven tests for both affected community modules with dependencies,
   verify the core snapshot is locally installed, and try the OneRing consumer
   build. Commit and push the new community branch; open the new community PR
   cross-linked to the core PR. Note any hosted-CI dependency limitation.

## Publication

10. Confirm both new PR links and branch heads. Draft short English comments
    for old core PR #6469 and old community PR #797 explaining the alternative
    generalization. Show exact text to the user and wait for explicit approval
    before posting either comment. Do not close the old PRs.
