The guardrail system was built in a composable way so it can be extended and reused in other downstream frameworks (such as [Quarkus](https://quarkus.io) or [Spring Boot](https://spring.io/projects/spring-boot)). This section describes some of the extension points or "hooks" that are provided.

All of these extension points utilize the [Java Service Provider Interface (Java SPI)](https://www.baeldung.com/java-spi).

| Extension point interface                                                                                                                                                                                    | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [`ClassInstanceFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/classloading/ClassInstanceFactory.java)                                     | Provides instances of classes.<br/> - Intended to delegate instance creation/retrieval to some other means.<br/> - If not provided, uses reflection to create an instance using the default constructor.<br/> - Other frameworks (like Quarkus or Spring) may use their own bean containers to provide instances of classes. Those frameworks would provide an implementation.<br/> - It also creates the [tool guardrail](/tutorials/tool-guardrails) classes (from `@ToolInputGuardrails`/`@ToolOutputGuardrails` and the `toolInputGuardrailClasses(..)`/`toolOutputGuardrailClasses(..)` setters), so a DI framework needs no tool-specific code for that.<br/> - A Quarkus implementation may look something like [`CDIClassInstanceFactory`](https://github.com/langchain4j/langchain4j/blob/main/integration-tests/integration-tests-class-instance-loader/integration-tests-class-instance-loader-quarkus/src/main/java/com/example/CDIClassInstanceFactory.java)<br/> - A Spring implementation may look something like [`ApplicationContextClassInstanceFactory`](https://github.com/langchain4j/langchain4j/blob/main/integration-tests/integration-tests-class-instance-loader/integration-tests-class-instance-loader-spring/src/main/java/com/example/classes/ApplicationContextClassInstanceFactory.java) |
| [`ClassMetadataProviderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/classloading/ClassMetadataProviderFactory.java)                     | Provides access to class metadata.<br/> - Used to scan the methods on `AiService` interfaces, and find and process the `@InputGuardrails`/`@OutputGuardrails` annotations, and the `@ToolInputGuardrails`/`@ToolOutputGuardrails` annotations of [tool guardrails](/tutorials/tool-guardrails).<br/> - Its `resolveMethodKey(Object)` method maps the `Method` seen at invocation time to the key your implementation uses for that method. The default returns the `Method` itself, so a framework whose method keys are not `Method`s (for example string keys) overrides it and then works with the default guardrail builders and services, blocking and non-blocking. It must return the same key for the same method, because callers cache the result. [`StringKeyedClassMetadataProviderFactory`](https://github.com/langchain4j/langchain4j/blob/main/integration-tests/integration-tests-class-metadata-provider/integration-tests-class-metadata-provider-string-keys/src/main/java/com/example/StringKeyedClassMetadataProviderFactory.java) is an example.<br/> - [`ReflectionBasedClassMetadataProviderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/classloading/ReflectionBasedClassMetadataProviderFactory.java) is the default implementation if no others are found, providing class metadata using reflection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| [`GuardrailServiceBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/service/guardrail/spi/GuardrailServiceBuilderFactory.java)                 | Provides builder instances for building [`GuardrailService`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/service/guardrail/GuardrailService.java) instances. An application or framework would implement this if they needed to customize the way they build `GuardrailService` instances.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| [`InputGuardrailsConfigBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/config/InputGuardrailsConfigBuilderFactory.java)   | - SPI for overriding and/or extending the default [`InputGuardrailsConfigBuilder`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/config/InputGuardrailsConfig.java)<br/> - Other frameworks may provide their own implementation with extra additional configuration for input guardrails.<br/> - Would also allow other frameworks to drive input guardrail configuration via some other mechanism (i.e. a properties file).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| [`OutputGuardrailsConfigBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/config/OutputGuardrailsConfigBuilderFactory.java) | - SPI for overriding and/or extending the default [`OutputGuardrailsConfigBuilder`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/config/OutputGuardrailsConfig.java)<br/> - Other frameworks may provide their own implementation with extra additional configuration for output guardrails.<br/> - Would also allow other frameworks to drive output guardrail configuration via some other mechanism (i.e. a properties file).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| [`InputGuardrailExecutorBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/InputGuardrailExecutorBuilderFactory.java)        | - SPI for overriding and/or extending the default `InputGuardrailExecutorBuilder` responsible for building [`InputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/InputGuardrailExecutor.java) instances.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| [`OutputGuardrailExecutorBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/OutputGuardrailExecutorBuilderFactory.java)      | - SPI for overriding and/or extending the default `OutputGuardrailExecutorBuilder` responsible for building [`OutputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/OutputGuardrailExecutor.java) instances.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| [`ToolGuardrailServiceBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/service/guardrail/spi/ToolGuardrailServiceBuilderFactory.java) | Provides builder instances for building [`ToolGuardrailService`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/service/guardrail/ToolGuardrailService.java) instances, which resolve and run the [tool guardrails](/tutorials/tool-guardrails) of each tool. The counterpart of `GuardrailServiceBuilderFactory` for tool guardrails. |
| [`ToolInputGuardrailExecutorBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/ToolInputGuardrailExecutorBuilderFactory.java) | SPI for overriding and/or extending the default builder responsible for building [`ToolInputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/ToolInputGuardrailExecutor.java) instances. |
| [`ToolOutputGuardrailExecutorBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/ToolOutputGuardrailExecutorBuilderFactory.java) | SPI for overriding and/or extending the default builder responsible for building [`ToolOutputGuardrailExecutor`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/guardrail/ToolOutputGuardrailExecutor.java) instances. |
| [`ToolInputGuardrailsConfigBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/config/ToolInputGuardrailsConfigBuilderFactory.java) | SPI for overriding and/or extending the default `ToolInputGuardrailsConfig` builder. | [`ToolOutputGuardrailsConfigBuilderFactory`](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/spi/guardrail/config/ToolOutputGuardrailsConfigBuilderFactory.java) | SPI for overriding and/or extending the default `ToolOutputGuardrailsConfig` builder. Other frameworks may provide their own implementation to drive tool output guardrail configuration via some other mechanism (i.e. a properties file). |

:::note
To customize guardrails, a framework provides a `ClassMetadataProviderFactory` and a `ClassInstanceFactory` and uses the default guardrail builders and services. It replaces the whole builder through `GuardrailServiceBuilderFactory` (or `ToolGuardrailServiceBuilderFactory`) only if it must. `AbstractGuardrailService` and `GuardrailService#aiServiceClass()` are deprecated since 1.25.0 and are not an extension point any more: use these SPIs and `targetClass()` instead.

`GenericGuardrailService` and its `Builder` are sealed, they are the shared contract that the per-kind interfaces specialize. `GuardrailService`, `ToolGuardrailService` and their builders are the extension points, so a framework can implement their builders, but it cannot add a new kind of guardrail service.
:::
